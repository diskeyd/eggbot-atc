# 공유받은 `변환 프로그램.exe` 비교

팀에서 공유받은 윈도우용 `변환 프로그램.exe`가 무엇인지, 우리 `eggbot-atc`와 무엇이 다른지 쉽게 정리했습니다.
결론만 먼저: **그림 미리보기·공부용으로는 괜찮지만, 이 프로그램이 만든 G-code를 우리 기계에 보내면 안 됩니다.**

## 1. 이 프로그램은 뭐예요?

- 이름: **EggBot Rotary ATC Master Simulator PRO**
- 파이썬으로 만든 창 프로그램을 exe 하나로 묶은 것입니다 (PyInstaller, Python 3.13, tkinter).
- 하는 일:
  1. G-code 파일을 연다.
  2. 색(레이어)이 바뀌는 곳을 찾는다 (`T`·`M6`·`M0`·`M1` 줄, 또는 "레이어·펜·색상·TOOL"이 들어간 주석). 못 찾으면 그냥 3등분한다.
  3. 색이 바뀌는 곳마다 "펜 바꾸기" 코드 9줄을 끼워 넣는다.
  4. 화면에 그림을 그려 보여 주고(미리보기·재생), 저장한다.
  5. G코드·M코드 설명표도 보여 준다.

### 안전한가요?

exe를 **실행하지 않고** 속을 열어 코드를 읽어 봤습니다 (2026-09-28).

- 쓰는 모듈은 `tkinter`(창), `os`, `re`(글자 찾기) 뿐입니다.
- 인터넷 연결, 다른 프로그램 실행, 비밀번호·쿠키 훔치기 같은 코드는 **없습니다**.
- 파일은 내가 고른 G-code를 읽고, 내가 고른 곳에 저장하는 것만 합니다.
- 함께 묶인 DLL 파일까지 전부 검사하진 않았습니다. 더 확실히 하려면 아래 지문(SHA-256)을 VirusTotal에서 검색해 보세요.
  `92123bfba46298999afa73f6212b8de76e111192fd62cd14df15423741525b0f`

## 3. 왜 우리 기계에 쓰면 안 돼요? (쉽게)

### ① 축 이름표가 서로 바뀌어 있어요
리모컨의 "채널 올리기"와 "소리 올리기" 버튼이 바뀐 것과 같아요.
그 프로그램이 "매거진 100만큼 앞으로!"(`Z100`)라고 하면, 우리 기계는 **매거진을 100도 돌려요**.
"매거진 45도 돌려!"(`A45`)라고 하면, 우리 기계는 **슬라이드를 45 mm 밀어요**. 부딪쳐서 부서질 수 있어요.

### ② 3번 펜이 1번 펜 자리에 가요
원을 한 바퀴 돌면(360°) 처음 자리(0°)로 돌아오죠.
그래서 0°, 180°, 360°로 나누면 1번과 3번이 **같은 자리**예요. 펜 3개는 120°씩 떨어져 있어야 해요.

### ③ 펜 내리기 숫자가 너무 세요
`M3 S` 뒤의 숫자는 각도가 아니라 "힘 세기"예요. `S0`을 주면 서보가 끝까지 확 튀어요.
우리는 `S30`처럼 적당한 값을 씁니다.

### ④ 숫자를 재지 않고 정해 놨어요
`Z100`, `Z80` 옆에 프로그램 스스로 "★실제 좌표로 수정 필요"라고 적어 놨어요.
우리는 기계를 직접 재서 `machine.toml`에 넣고, 안 잰 값(TODO)이 있으면 변환을 **거부**해요.

### ⑤ 펜 바꾸는 방법이 달라요
그 프로그램은 매거진을 돌려서 펜을 "낚아채는" 방식이고, X(펜 캐리지)는 가만히 있어요.
우리 기계는 캐리지가 매거진 쪽으로 가서 펜을 꽂고 빼는 방식이에요. 숫자만 고쳐서는 맞출 수 없어요.

### ⑥ 펜을 바꾼 뒤 제자리로 안 돌아가요
그 프로그램은 펜을 바꾸고 나서 원래 그리던 자리로 돌아가지 않아요. 그래서 다음 선이 엉뚱한 곳에서 시작돼요.

## 4. 그럼 어떻게 써요?

- ✅ G-code 공부, 그림 미리보기, 코드표 보기 → 써도 됨 (윈도우에서만 실행됨)
- ❌ 저장한 G-code를 기계로 보내기 → **안 됨**
- 실제로 기계에 보낼 G-code는 README 순서대로 `uv run eggbot-atc`로 만드세요.
- 미리보기 기능이 좋으면, 파이썬 소스(`.py`)를 받아 우리 축 배정에 맞게 고치는 걸 같이 얘기해 봐요.

## 5. 왜 이렇게 만들었을까? 우리 코드에 가져올 건?

코드를 읽고, 만든 사람이 어떤 생각이었을지 짐작해 보고 하나씩 따져 봤습니다.

| 조원 프로그램의 선택 | 왜 그랬을까 (추정) | 우리에게 쓸모 | 결론 |
|---|---|---|---|
| 매거진을 45° 돌렸다가 0°로 되돌리며 펜 "낚아채기" | 돌려서 끼우는 **트위스트(돌려 잠금) 방식** 기구를 생각한 것 | 우리 기구는 캐리지가 X로 밀고 빼는 방식. 어느 쪽이 실제로 잘 잡히는지는 **기구를 만들어 봐야** 앎 | 코드엔 안 넣음. 팀 회의 안건 |
| Z를 매거진 앞뒤 이동으로 씀 | 흔한 CNC처럼 "Z = 위아래/앞뒤"라고 생각 | 우리는 README 축 배정표(Z=회전, A=슬라이드)를 이미 정함 | 안 가져옴 |
| 좌표를 코드에 고정 | 빨리 시뮬레이터부터 보여 주려고 | 측정 전 값으로 기계가 움직이면 위험 | 안 가져옴 (우리는 TODO면 거부) |
| 여러 형태의 펜 교체 줄 인식 | 다른 CAM 프로그램이 만든 G-code도 받으려고 | **검증해 보니 우리 코드는 `M06 T2`, `M6T2`, `N10 T2 M6`를 못 알아봤음.** 이러면 펜 교체 없이 한 색으로 끝까지 그려 버림 | ✅ **가져옴** (아래) |
| `M0`/`M1`, 주석 글자로 색 전환 추측 | 펜 번호가 없는 G-code도 살려 보려고 | 추측이 틀리면 엉뚱한 곳에서 펜을 바꿈. 우리는 SVG 레이어로 확실히 정함 | 안 가져옴 |
| 전환점 없으면 3등분 | 데모가 항상 "뭔가" 보여 주게 | 실제 그림을 망침 | 안 가져옴 |
| 같은 파일 두 번 변환 막기 | ATC 코드가 두 번 들어가는 걸 막으려고 | 우리는 `T` 줄을 매크로로 **바꿔치기**해서 결과 파일엔 `T` 줄이 없음. 다시 돌려도 안 겹침 | 이미 해결됨 |
| 2D 미리보기·재생 | 발표·이해용 | UGS에 이미 경로 미리보기(Visualizer)가 있음 | 지금은 안 만듦. 필요하면 소스 받아서 붙이기 |

### 가져온 것: 펜 교체 줄 인식 넓히기

- 전에는 `T2`, `M6 T2`, `T2 M6`만 알아봤습니다.
- 이제 `M06 T2`(0 붙은 형태), `M6T2`(띄어쓰기 없음), `N10 T2 M6`(줄 번호 붙음)도 알아봅니다.
- `G0 X1 T2`처럼 줄 중간에 있는 `T`는 여전히 무시합니다 (펜 교체가 아님).
- 테스트: `tests/test_pipeline.py`의 `test_cam_tool_line_forms`.

## 6. 이 코드는 어떻게 만들어졌을까?

확실히는 모릅니다. 다만 코드에 남은 흔적으로 보면 **AI 도구(ChatGPT·Gemini 등)로 만든 코드일 가능성이 높아 보입니다.**
AI로 만드는 건 흔하고 문제가 아닙니다. 다만 **우리 기계 정보 없이** 만들어졌다는 점이 중요합니다.

| 흔적 | 예 |
|---|---|
| 이름이 크고 화려함 | `UltimateATCGCodeApp`, "Master Simulator PRO", "9단계 정밀", "완벽 가이드" |
| 이모지가 아주 많음 | 🎨 💡 💾 📁 🔍 🎉 ✨ ⚡ 가 버튼·제목마다 |
| 색이 웹 디자인 도구(Tailwind CSS) 기본 색 그대로 | `#0F172A`, `#2563EB`, `#10B981`, `#EF4444` |
| G-code에 번호 붙은 교과서식 설명 | "1. 수평 정렬 … 9. 그리기 준비", "★실제 좌표로 수정 필요" |
| 우리 기계를 모르고 짠 흔적 | 흔한 CNC처럼 Z를 앞뒤 이동으로 사용, 펜 각도 0/180/360° |

인터넷 코드를 그대로 복사했을 가능성은 낮습니다. 한국어 문구가 곳곳에 있고, 에그봇 ATC는 공개된 코드가 거의 없는 좁은 주제이기 때문입니다.

**앞으로는:** 코드를 만들 때(AI를 쓰든 안 쓰든) README의 **축 배정표**와 `machine.toml`을 먼저 보고 맞춰 주세요. 좋은 아이디어(예: 미리보기 화면)는 이슈로 올려 주면 이 저장소에 합칠 수 있습니다.

### 팀에서 정할 것

- ⑤번은 버그가 아니라 **기구 방식의 차이**입니다. 2번째 버전은 "슬라이드를 붙이고 매거진을 45° 돌려 갈퀴로 펜을 걸고 빼는" 방식, 우리 코드는 "펜 암(X)이 매거진 쪽으로 돌아가 자석+핀으로 붙였다 떼는" 방식입니다. 실제 펜 고정부·매거진이 어느 쪽으로 만들어졌는지 정하면, 우리 `atc.py` 매크로 순서를 그쪽에 맞추겠습니다.
- ①~④, ⑥, ⑦은 방식과 상관없이 고쳐야 하는 버그입니다. 미리보기용으로는 써도 되지만, 저장한 G-code는 기계로 보내지 마세요.

### 결정 (2026-10-09)

펜 교체는 **2번째 버전의 방식(매거진 45° 돌려 갈퀴로 걸기)** 으로 정했습니다. 우리 `atc.py` 매크로를 이 순서로 바꿨고, ①~④·⑥·⑦ 버그는 넣지 않았습니다. 순서는 README "ATC 펜 교체"에 있습니다. 2번째 버전의 장착 순서(갈퀴를 슬롯 각도에 두고 밀착 → 45° 돌려 놓기)와 반납 순서(45° 비켜 두고 밀착 → 슬롯 각도로 감싸기 → 팔 후퇴 → 슬라이드 후퇴)를 따랐습니다. 2번째 버전은 교체 중에 새 펜을 `release_x`에서 받는데, 반납과 같은 `park_x`에서 받도록 맞췄습니다.

## 8. 고쳐서 다시 만든 윈도우 프로그램 `EggBot-ATC.exe` (2026-10-09)

팀원 프로그램(`peneggbot1.exe`)의 **화면은 그대로** 두고, 기계로 가는 G-code는 이 저장소의 테스트된 코드(`eggbot-atc`)가 만들게 고쳤습니다.
화면 코드는 exe 안의 파이썬 바이트코드를 한 줄씩 되살린 것이고(원본과 바이트코드 일치 확인), 창을 만드는 부분(`create_main_ui`)은 원본과 똑같습니다. 코드: `src/eggbot_atc/gui.py`.

### 받는 법

GitHub 저장소 → **Actions** → `build-exe` → 가장 최근 실행 → 맨 아래 **Artifacts**의 `EggBot-ATC-windows`. 코드를 고쳐 `main`에 올리면 자동으로 새로 만들어집니다.
처음 실행하면 exe 옆에 `machine.toml`이 생기고, [⚙️ 기계 물리 설정]에서 고친 값은 이 파일에 저장됩니다.

### 고친 것

| | 팀원 프로그램 | 고친 프로그램 |
|---|---|---|
| 1 | 서보 대기 `G4 P300` = **300초** | `G4 P0.3` = 0.3초 |
| 2 | 펜 교체 뒤 원점에서 펜 내림 → 엉뚱한 선 | 펜 든 채 그리던 자리로 이동 후 펜 내림 |
| 3 | 펜 각도 0°, 180°, 360° (1번 = 3번) | 120° 간격 |
| 4 | 펜 내림 `M3 S0` (서보가 끝까지 튐) | 설정의 펜 내림 명령 |
| 5 | 선(path id)마다 펜 교체 | `T` 줄(SVG는 레이어)이 바뀔 때만 |
| 6 | `M6` 줄이 남아 GRBL이 멈춤 | `T`/`M6` 줄을 펜 교체 동작으로 바꿔치기 |
| 7 | 교체 중 새 펜을 `release_x`에서 받음 | `park_x`에서 받음 |
| 8 | 설정이 꺼지면 사라짐, 안 잰 기본값이 그대로 나감 | `machine.toml`에 저장. 안 잰 값이 있으면 **미리보기만, 저장은 막음** |
| 9 | 설정 창 6칸 (쓰이지 않는 `Dock X` 포함) | 12칸: 측정 체크리스트의 값 + 갈퀴 회전각 + 펜 올림/내림 명령 |
| 10 | G-code만 열림 | **SVG도 열림** (Inkscape 레이어마다 색 고르기) |
| 11 | 변환 누르면 고른 색이 기본값으로 돌아감 | 고른 색 그대로 변환 |
| 12 | 미리보기에 펜 교체 이동(교체 위치·슬라이드)이 섞여 그림이 찌그러짐 | 펜 교체 이동은 빼고 그림만, 가로·세로 따로 맞춤 |
| 13 | 코드표 "G04 P2000 = 2초", "M05 = 펜 올림" | GRBL 기준으로 고침 (P는 초, M05는 서보에 쓰지 않음) |
| 14 | 코드 분석 "X = 펜 좌우 이송" | "X = 펜 암 회전(도)", A·Z 단위 표시 |

G-code 파일을 열었을 때 마지막 펜을 매거진에 돌려놓지 않던 문제는 이 저장소의 명령어 버전(`eggbot-atc convert`)에도 있어서 같이 고쳤습니다.

### 그대로 둔 것

화면 모양·색·버튼·이모지, 레이어 색 매칭, 줄 편집, 실시간 코드 분석, 실무 코드표, 2D 미리보기·재생·배속. 버튼 이름 "✨ ATC 6단계 변환"도 그대로입니다.

### 확인 안 된 것

- 이 Mac에서 창을 띄워 SVG 열기 → 색 고르기 → 변환 → 저장 막힘까지 자동 테스트로 확인했습니다. **윈도우에서 직접 눌러 본 것은 아닙니다.** exe는 GitHub의 윈도우 서버가 테스트를 통과한 뒤에 만듭니다.
