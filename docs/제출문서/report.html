1. 프로그램 개요

에그봇 G-code 생성기는 이미지에서 선과 영역을 추출해 달걀 또는 공 표면에 그림을 그리기 위한 G-code를 만드는 Windows용 프로그램이다. GRBL 컨트롤러와 USB로 연결하면 생성한 G-code를 기계로 전송한다.

1-1. 주요 기능

  • 이미지 불러오기, 자동 선·영역 추출
  • 색상별 영역 지정, 펜 색상 배정
  • 영역 채우기, 테두리 그리기, 지그재그 채우기
  • 직접 선 그리기, 지우개
  • 물체 크기·위치·회전 조정 (달걀 / 탁구공 / 골프공)
  • 3D 미리보기, G-code 확인·수정
  • 1~3개 펜 설정, 회전식 펜 매거진(ATC) 설정, 교환 순서 미리보기, 교환 시험
  • USB 시리얼 GRBL 연결, G-code 전송, 일시정지·재개·정지
  • 작업 파일 저장·불러오기, 20초 간격 자동 저장

2. 설치

2-1. EXE 배포본을 받은 경우

사용자는 Python을 설치하지 않는다. 다음 순서로 준비한다.

  1. 전달받은 압축 파일을 푼다.
  2. 압축을 푼 폴더에서 EggBot.exe(또는 배포자가 지정한 실행 파일)를 찾는다.
  3. USB 연결용 Windows 드라이버를 설치한다. 컨트롤러가 COM 포트로 보여야 한다. (4장 참고)
배포 방식별 유의사항 단일 파일 방식 EXE는 실행 파일만 있으면 된다. 폴더 방식은 EXE를 따로 꺼내지 않는다. 함께 들어 있는 폴더와 파일을 그대로 둔다.

2-2. Python 소스로 설치하는 경우 (개발·EXE 제작 담당)

  1. Python을 설치한다. Tkinter가 포함된 배포판을 쓴다.
  2. 패키지를 설치한다.
python -m pip install pillow pyserial pyinstaller
  1. 소스 파일 캡스톤 디자인2_13분반_3조_프로그램.py를 작업 폴더에 둔다.

2-3. EXE 직접 만들기

pyinstaller --noconfirm --clean --onefile --windowed --name EggBot "캡스톤 디자인2_13분반_3조_프로그램.py"
  • 결과물은 보통 dist 폴더에 생긴다.
  • 빌드 후 다른 PC에서 EXE를 실행한다. 이미지 열기와 USB 포트 검색까지 확인한다.
  • 포트 검색이 EXE에서 안 되면 PyInstaller 빌드 로그와 pyserial 포함 여부를 확인한다.
검증 범위 이 문서를 작성한 환경은 macOS이다. EXE 빌드와 Windows 실행은 이 환경에서 하지 않았다. 위 명령은 README 기준을 그대로 옮긴 것이다. 소스 구문 검사(Python AST 파싱)만 통과를 확인했다.

3. 실행

3-1. EXE 실행

  1. 실행 파일을 더블클릭한다.
  2. 메인 창 제목이 에그봇 G코드 생성기로 표시되면 실행된 것이다.
  3. 창 크기는 1380×900이다. 최소 크기는 1100×720이다.

3-2. 소스 직접 실행

python "캡스톤 디자인2_13분반_3조_프로그램.py"

진입점은 파일 끝의 main()이다. App().mainloop()를 호출한다. Pillow가 없으면 main()이 설치 안내 문구를 출력한다. 이미지 처리는 Pillow가 필요하다.

3-3. 이전 작업 복원

프로그램은 20초마다 작업을 자동 저장한다. 다시 실행하면 이전 작업이 복원된다. 새 작업은 새로 시작을 누른다. 필요한 기존 작업은 먼저 .eggbot 파일로 저장한다.

3-4. 실행이 되지 않는 경우

  • Windows가 실행 파일을 차단하거나 오류 창을 띄우면, EXE가 정상 빌드되었는지 확인하고 제작자에게 문의한다.
  • 이미지가 열리지 않으면 EXE에 Pillow가 포함되었는지 확인한다.
  • 포트가 보이지 않으면 6장과 8장을 확인한다.

4. 의존성

4-1. EXE 사용자

정상 패키징된 EXE에는 Python 실행 환경과 라이브러리가 들어 있다. 별도 Python 설치는 필요 없다.

단, 보드의 USB-시리얼 드라이버는 EXE에 들어 있지 않다. PC가 컨트롤러를 COM 포트로 인식해야 한다.

4-3. 펌웨어 의존성

PC 쪽 라이브러리와 별개로, 컨트롤러 펌웨어가 다음을 지원해야 실제 기계가 움직인다. 자세한 내용은 6장에 있다.

  • 5축 이상 (ATC 매거진 축 Z, 접근 축 A). 기본 GRBL 1.1은 3축이라 error:20이 난다.
  • 서보 명령 M96 A값. 소스는 grbl-Mega-5X-servos 계열 펌웨어를 기준으로 한다.

5. 기본 사용 순서

5-1. 이미지 불러오기

  1. 왼쪽 1. 이미지 열기를 누른다.
  2. PNG/JPG/JPEG/BMP/GIF/WEBP 파일을 고른다.
  3. 가운데 작업 화면에 이미지가 나오는지 확인한다.

긴 변이 1400 px보다 크면 줄이고, 1000 px보다 작으면 부드럽게 키운 뒤 윤곽을 딴다.

왼쪽 선 추출 탭에서 조절한다.

항목설명

가운데 작업 화면의 도구는 네 가지이다: 영역 채우기, 색 칠하기, 직접 그리기, 지우개. 직접 그린 선도 G-code에 들어간다.

추출 결과가 예상과 다르면 방식을 바꾸고 민감도와 최소 영역 크기를 조정한다. 추출 설정을 바꾸면 채우기 선택이 초기화될 수 있다. 영역을 다시 지정한다.

5-3. 물체와 위치 설정

  • 물체 종류: 달걀, 탁구공, 골프공. 길이·지름·뾰족함을 입력한다.
  • 그림의 회전 위치, 세로 위치, 세로 크기, 가로 배율, 회전 각도를 조정한다. 오른쪽 펼친 모습 창에서 드래그로도 조정한다.
  • 펜 팔 최대 각도를 설정한다.

화면의 미리보기와 실제 기계의 물체 크기·원점·펜 위치가 일치하는지 확인한다.

5-4. 펜과 속도 설정

펜·속도 탭에서 펜 올림/내림 값, 딜레이, 그리기 속도, 이동 속도를 설정한다. 서보와 펌웨어에 맞는 값인지 먼저 시험한다.

5-5. 3D 미리보기와 G-code 확인

  1. 3D 미리보기 창 열기로 그림 경로를 확인한다.
  2. ATC를 쓰면 펜 교환 설정 창에서 교환 순서를 확인한다.
  3. G코드 확인·수정에서 명령과 좌표를 점검한다.
  4. 필요하면 G코드 저장으로 .gcode 파일을 저장한다.
저장 경로에 따라 서보 명령이 다르다 메인 창의 G코드 저장은 M3 S를 M96 A로 바꿔 저장한다. G코드 확인·수정 창의 저장은 화면 텍스트를 그대로 저장한다 (소스 확인). 기계에 보낼 파일은 메인 창의 저장 또는 직접 전송을 쓴다.

5-6. 작업 저장과 불러오기

  • 작업 저장: 이미지, 영역 선택, 펜 지정, 작업 설정을 .eggbot으로 저장한다.
  • 작업 불러오기: .eggbot 또는 지원되는 .json을 연다.
  • 새로 시작: 현재 작업을 초기화한다.
  • ATC 메커니즘 설정은 작업 파일과 별도 파일에 저장된다 (7-5 참고).

6-4. 펌웨어 호환

축

ATC 매거진 축과 접근 축까지 쓰려면 5축 이상 펌웨어가 필요하다. 기본 GRBL 1.1은 X/Y/Z 3축이다. A축 명령에서 error:20이 난다. 사용하는 보드·펌웨어가 지원하는 축 문자와 이동 범위를 먼저 확인한다.

펜 서보 명령

화면의 펜 올림/내림 값은 M3 S값이다. 기계로 전송하거나 G-code를 저장할 때 프로그램이 이것을 M96 A값으로 바꾼다.

설정 (소스 상수)값
SERVO_M96True (변환 사용)
SERVO_CHANNEL"A" → RAMPS SERVO0 / D11
SERVO_INVERTTrue (A = 499 − A)
변환식A = round(S × 499 / 180), S는 0~180으로 제한
 
M3 S90  →  G4 P0 / M96 A249     (pen_up 기본값)
M3 S30  →  G4 P0 / M96 A416     (pen_down 기본값)

M96은 GRBL의 이동 큐와 동기화되지 않는다. 그래서 변환할 때 앞에 G4 P0(이동이 끝날 때까지 대기)을 붙인다.

일반 GRBL만 올린 보드는 M96을 모른다. G-code가 화면에 보여도 서보가 움직이지 않는다. 서보 채널, 방향, 배선이 프로그램 설정과 맞는지 확인한다.

6-5. 물리 구성 참고 (저장소 하드웨어 문서)

  • 보드: Arduino Mega 2560 R3 + RAMPS 1.4. 스텝 드라이버 DRV8825 4개 (1/32 마이크로스텝 점퍼).

  • 엔드스탑은 아직 달지 않았다. 원점은 손으로 맞춘다 (프로그램의 여기를 원점으로 사용).

7-5. 설정 파일 저장 위치

ATC 메커니즘 설정 창의 저장 버튼을 눌러야 별도 파일에 저장된다. 창 아래쪽에 빨간 저장 안 됨이 보이면 아직 저장 전이다. 이 설정은 작업 파일, 새 작업과 별개로 유지된다.

%USERPROFILE%\.eggbot_studio\atc_settings.json   (ATC 메커니즘 설정)
%USERPROFILE%\.eggbot_studio\autosave.json       (자동 저장 작업, 20초 간격)

프로그램은 시작할 때 ATC 설정 파일을 읽어 ATC 관련 필드를 덮어쓴다. 작업 파일의 ATC 값보다 설정 파일이 우선한다.

GRBL ALARM 표시홈·리밋·이동 범위 또는 좌표 설정 문제원인을 먼저 확인하고 기계가 안전한 상태인지 본 뒤 필요하면 $X. 잠금 해제만으로 원인이 해결되지 않는다.
G-code 범위 초과 경고그림 위치·크기·회전이 기계 작업 영역 밖위치·크기를 줄이거나 이동. 축 설정과 최대 이동 범위 확인. (범위 초과 상태에서는 그리기 시작이 막힌다.)
저장한 ATC 설정이 다음 실행에 적용되지 않음설정 창에서 저장하지 않음, 또는 사용자 폴더 쓰기 실패ATC 메커니즘 설정 창에서 저장 클릭. %USERPROFILE%\.eggbot_studio 쓰기 권한 확인.
프로그램을 다시 켰더니 이전 그림이 나타남자동 저장 작업 복원 기능새 작업은 새로 시작. 필요한 기존 작업은 먼저 .eggbot으로 저장.

9. 안전 주의사항

  1. 사진 속 수치는 참고 입력값이다. ATC 대기 −10 mm, 도킹 −248 mm, 슬롯 간격 5.3° 등은 실제 장비의 측정값과 기구 치수에 맞는지 확인한다.
  2. ATC 교환 시험은 실제 모터를 움직인다. 3D 미리보기만 보고 바로 시험하지 않는다. 펜·달걀·주변 장애물과 충돌할 가능성을 확인한다. 처음에는 펜을 빼고 낮은 속도로 단계별로 시험한다.
  3. 소프트 리밋 자동 해제. 작업 준비 과정에서 GRBL $20이 켜져 있으면 프로그램이 $20=0을 사용자 확인 없이 보낸다. 이 값은 컨트롤러에 저장된다. 로그에는 "다시 켜려면 직접 명령창에 $20=1"이라고 남는다. 실행 전에 $20 상태와 기계의 물리적 이동 한계를 확인한다. 소프트 리밋이 꺼지면 범위를 넘는 이동을 소프트웨어가 막지 못한다.
  4. 비상 정지는 소프트웨어 정지이다. GRBL 홀드(!)와 소프트 리셋(Ctrl-X)을 보낸다. 물리 비상정지 스위치를 대신하지 않는다. 위험하면 물리 비상정지나 전원 차단을 쓴다.
  5. 서보·스테퍼 전원과 배선을 확인한다. 보드 핀, 서보 채널, 드라이버, 모터 전압, 공통 접지가 실제 회로와 일치해야 한다.
  6. 자가 점검과 3D 미리보기는 기계 안전을 보증하지 않는다. 좌표, ATC 이동, 펜 올림/내림을 직접 확인하고 저속·무부하로 먼저 시험한다.
  7. 종료 절차. 작업이 끝나면 펜을 올리고, 기계를 안전한 위치에 두고, 연결을 해제하고, 전원을 끈다.
취소·오류 중단 시 동작 작업 취소(초기화)는 소프트 리셋 없이 대기열만 지운다. 이미 GRBL 버퍼에 들어간 마지막 몇 개 이동은 그대로 끝난다 (소스 주석). GRBL 오류로 작업이 중단될 때 펜을 자동으로 올리는 명령은 소스에 없다. 중단 후에는 펜 상태를 직접 확인한다.

10-1. 화면 구성

  • 왼쪽 패널: 이미지 열기, G코드 저장, G코드 확인·수정, 3D 미리보기, 작업 저장·불러오기, 도구 창 열기(원점 자동 조정, 보정, 자가 점검). 탭 5개: 물체 / 선 추출 / 위치·크기 / 펜·속도 / 펜 교환(ATC).
  • 가운데 패널: 원본 이미지와 도구(영역 채우기, 색 칠하기, 직접 그리기, 지우개), 펜 팔레트, 채우기 옵션(간격 0.3~2.0 mm, 각도 0~90°).
  • 오른쪽 패널: 펼친 모습. 달걀 표면을 각도–mm 격자로 펼친 화면이다. 범위 밖 영역은 붉게 표시한다. 상자 이동·크기·회전 핸들과 마우스 휠 조작을 지원한다.
  • 아래 패널: 포트, 연결, 펜 올림/내림, 원점, 조그, 그리기 시작, 일시정지, 비상 정지, 진행률, 직접 명령, 로그.

10-2. 스레드와 통신 구조

시리얼 송수신은 작업 스레드 1개가 맡는다. UI(Tk 메인 스레드)는 queue.Queue 이벤트 큐로만 통신한다. UI는 60 ms마다 큐를 비우며 로그, 상태, 진행률, 완료, 준비 완료 이벤트를 처리한다.

  • 스트리밍: 한 줄씩 보내면서 미확인 바이트 합이 RX_LIMIT = 118(GRBL 수신 버퍼 127바이트 미만)을 넘지 않게 한다. ok를 받으면 빼 준다.
  • 상태 조회 ?를 약 0.6초마다 보낸다.
  • 일시정지 !, 재개 ~, 비상 정지는 ! 후 Ctrl-X(0x18).
  • error/alarm을 받으면 줄 번호·원문·한국어 설명을 기록하고 작업을 멈춘다. 오류 기록 창에서 본다.
  • 작업 시작 전 준비 단계에서 알람 해제($X)와 $20 확인을 한다 (9장 참고).

10-3. 저장 형식

.eggbot은 JSON 텍스트이다. 앱 이름, 버전, Params, 축 설정, 이미지 이름, 이미지 PNG(base64), 선택된 영역, 영역별 펜, 원점 정보, 직접 그린 선을 담는다. 쓸 때는 임시 파일에 먼저 쓰고 os.replace로 교체한다. 쓰다가 중단돼도 기존 파일이 깨지지 않는다.

11. 핵심 알고리즘

11-1. 영역 추출 (Artwork.analyze)

모드처리
자동(배경 제거)테두리 픽셀의 채널별 중앙값을 배경색으로 잡는다. 각 픽셀과 배경색의 RGB 거리가 bg_tol보다 크면 전경이다. 닫힘(closing)과 중앙값 필터로 잡티를 정리한다. 전경 비율이 0.2~85 %면 채택한다. 실패하면 Otsu 임계값, 그래도 실패하면 회색조 Otsu, 마지막으로 밝기 임계값을 쓴다. 선택 이유를 화면 메모로 알려 준다.
색 영역 나누기Median-cut으로 색을 줄인다 (2~16색, 기본 6). 팔레트 색 거리가 color_merge 이하이면 union-find로 합친다. 같은 값의 4-연결 성분을 영역으로 삼고, 배경과 너무 작은 영역을 버린다. 맞닿은 영역의 중복 윤곽은 제거한다.
어두운 선(밝기)밝기가 임계값(기본 128)보다 어두운 픽셀이 선이다.

공통 후처리: flood_label이 4-연결 성분을 만들고 최소 영역보다 작은 덩어리를 지운다. trace_outlines는 픽셀 경계 변으로 방향 간선을 만든 뒤, 꼭짓점 그래프를 따라 닫힌 루프를 이어 윤곽을 얻는다. 안쪽 구멍 경계도 함께 얻는다.

11-2. 선 생성 (Artwork.build)

  1. 축척: mmpp = height_mm / 이미지 높이(px).
  2. 테두리: [1 2 1]/4 필터로 부드럽게 한 뒤 RDP로 단순화한다. 허용 오차는 max(0.5 px, simplify_mm / mmpp)이다. dedupe_overlap이 이미 그린 구간과 겹치는 부분을 한 번만 남긴다.
  3. 채우기: 선택된 영역만 채운다. 각도 fill_angle(기본 45°)의 평행선을 fill_gap_mm(기본 0.5 mm) 간격으로 긋는다. 지그재그 옵션이 켜져 있으면 이웃 줄을 번갈아 뒤집어 잇는다. 이을 구간이 모두 영역 안일 때만 잇고, 아니면 펜을 든다.
  4. 직접 그린 선: RDP로 단순화한다 (허용 오차 max(0.4 px, 0.2 mm / mmpp)).
  5. 높이 제한: 펜 팔이 닿는 한계 높이 hlim = min(반길이 × 0.995, arm_len × sin(arm_max_deg) × 0.999)를 넘는 점에서 선을 끊는다. 기본값에서 약 28.25 mm이다.

11-3. 달걀 표면 매핑 (to_surface, Shape)

dx = (x - cx) * stretch_x ;  dy = y - cy
rx = dx*cos(rot) - dy*sin(rot) ;  ry = dx*sin(rot) + dy*cos(rot)
deg = pos_x_deg + rx * mmpp * 360 / circumference(pos_y_mm)
h   = pos_y_mm  - ry * mmpp            # 이미지 y는 아래가 +

radius(h) = R * sqrt(1 - v^2) * (1 + p*v),  v = h / half   # R=지름/2, p=pointiness

이미지 좌표를 (회전각 deg, 높이 h) 표면 좌표로 바꾼다. 가로 mm를 각도로 바꿀 때는 pos_y_mm 높이의 원주를 쓴다. 따라서 달걀의 끝으로 갈수록 실제 폭이 좁아진다 (한계로 13장에 적었다).

11-4. 펜 팔 좌표 변환 (arm_out)

펜 팔 모델은 h = L · sin θ이다 (L = arm_len_mm 기본 40 mm). 높이 h를 팔 각도 θ로 바꿔 X축 값으로 쓴다. θ는 ±arm_max_deg(기본 45°)로 제한된다. 회전각 deg는 deg × cal_rot_scale + cal_rot_off로 보정하고 Y축 값으로 쓴다. 축 설정에 따라 X/Y를 바꾸거나 반전한다.

11-5. 그리는 순서 (order_by_pen, order_strokes)

  • 펜 번호 순으로 묶는다. 면적 큰 색부터를 켜면 면적 순이다. 같은 펜 안에서는 채우기 → 테두리 → 직접 그린 선 순서이다.
  • 각 묶음은 가장 가까운 시작점을 고르는 탐욕 정렬이다. 거리는 각도를 mm로 바꿔 계산한다. 선이 2500개를 넘으면 3 mm 띠 단위 훑기로 근사한다.
  • 닫힌 선은 가장 가까운 꼭짓점에서 시작하도록 돌린다. 필요하면 선 방향을 뒤집는다.

11-6. 딤플 보정 (골프공)

3D 미리보기에는 딤플 무늬를 그린다. G-code에는 무늬가 아니라 보정만 들어간다. 자동 모드는 선을 1 mm로 쪼개고, 딤플 안쪽·가장자리 구간에서 속도를 45 %로 줄이고 펜을 8만큼 더 누른다. 선 길이의 15 % 이상이 딤플 구간이면 같은 선을 반복할 수 있다 (기본 반복 횟수 1).

12. G-code와 ATC 교환 시퀀스

12-1. G-code 구조 (build_gcode)

  1. 헤더 주석(색 순서, 보정값)
  2. G21, G90, 펜 올림 M3 S<pen_up>
  3. 펜을 2개 이상 쓰고 ATC 모드이면 초기 자세 G0 Z<각도> A<대기>
  4. 선마다: 펜이 바뀌면 교환 블록 → G0 X Y (이동) → 펜 내림 → G4 → G1 … (그리기) → 펜 올림 → G4
  5. 끝: 펜 올림, (옵션) 처음 펜으로 되돌려 교체, (옵션) G0 X0 Y0, M2

이 프로그램은 G92나 홈 명령을 G-code에 넣지 않는다. 시작 시점의 기계 좌표를 0으로 가정한다. 작업 전에 여기를 원점으로 또는 원점 도구 창으로 원점을 맞춘다.

12-2. 기본 펜 교환 순서

펜 교환은 텍스트 스크립트(mech_script)로 정의된다. 소스의 기본 스크립트가 만드는 순서는 다음과 같다. 변수 A = 뗄 펜 슬롯 각도, B = 끼울 펜 슬롯 각도, H = 접근 보정각, DOCK/PARK = 도킹/대기 위치이다.

스크립트 문법은 단순하다. 명령은 carriage, turret, atc, wait, mount, gcode이다. 조건은 when 조건: 접두로 붙인다. 수식은 ast 모듈로 검사해 사칙연산, 비교, min/max/abs만 허용한다. 임의 코드는 실행되지 않는다. 기구가 바뀌면 코드를 고치지 않고 스크립트만 고친다. mount 단계는 G-code를 출력하지 않는다 (소스: 출력 없음). mech_compile은 충돌 위험(도킹한 채 매거진 회전 등)을 경고한다.

12-3. 자가 점검 (run_selfcheck)

자가 점검 창은 다음을 검사해 ok / 경고 / 오류로 표시한다.

  • Pillow·pyserial 설치, 자동 저장 폴더 쓰기 가능 여부
  • 펜 올림/내림 값 차이(10 이상), 그리기 속도와 이동 속도 관계, 보정 배율 범위(0.8~1.25)
  • ATC 축 글자가 한 글자이고 서로 겹치지 않는지, 5축 펌웨어 필요 안내
  • G-code 끝의 M2와 펜 올림
  • GRBL $$ 값: $30, $100/$101, 속도·이동 한계
  • 연결 후 3초 넘는 무응답, 이번 실행에서 원점을 정했는지

자가 점검은 참고용이다. 그리기 시작은 자가 점검을 강제하지 않는다. 범위 초과(out_of_range)만 시작을 막는다.

13. 한계 및 향후 과제

이 장은 소스 읽기와 저장소 문서에서 확인한 한계를 적는다. 프로그램을 실행하거나 기계에 연결해 확인한 것이 아니다.

13-1. 검증 범위

  • 기계 실측과 실기 시험 결과는 이 문서에 없다. 설정값은 설정 화면과 소스 초기값이다.
  • 서보 M96 동작, 시리얼 스트리밍, ATC 이동 수치는 실기에서 확인해야 한다.
  • EXE 빌드와 Windows 실행은 이 문서 작성 환경(macOS)에서 하지 않았다.

13-2. 펌웨어와 하드웨어 의존

  • 5축 + M96 펌웨어 필수. 일반 GRBL 1.1은 ATC 축과 서보 명령을 처리하지 못한다.
  • 저장소 설계와 서보 방식이 다르다 (M96 A/D11 대 D6 스핀들 PWM). 실제 기계의 배선과 펌웨어를 프로그램 설정에 맞춘다 (6-4).
  • 엔드스탑이 없으면 원점을 손으로 맞춘다. 중간에 멈춘 작업은 펜 위치를 손으로 정리해야 한다.

13-3. 알려진 제한과 개선 항목

#항목설명과 개선 방향
1메인 패널 조그 버튼소스에서 조그가 grbl.send_raw를 호출하는데 GrblLink에 해당 메서드가 없다. 이 경로의 버튼 동작은 보장되지 않는다. 원점 도구 창의 조그는 별도 경로로 구현되어 있다. 연결 후 GrblLink.send를 쓰도록 고친다.
2소프트 리밋 자동 해제준비 단계에서 $20=0을 확인 없이 기록한다. 사용자 확인 대화상자를 추가한다.
3교환 시 서보 값 고정교환 순서가 M3 S160을 고정 출력한다. 펜 올림 설정과 연동한다.
4G-code 저장 경로 차이메인 저장은 M96으로 변환하고 편집창 저장은 원문 그대로이다. 저장 방식을 통일한다.
5표면 매핑 왜곡가로 mm를 각도로 바꿀 때 한 높이의 원주만 쓴다. 높이별 원주로 보정한다.
6시간 추정 이중 계산G-code 통계의 예상 시간과 3D 재생 시간이 서로 다른 방식으로 계산된다. 하나로 합친다.
7긴 G-code 줄한 줄이 118바이트를 넘으면 전송이 멈출 수 있다. 사용자 정의 교환 G-code를 짧게 쓰거나 전송기에서 거른다.
8ATC 설정 우선순위시작할 때 ATC 설정 파일이 작업 파일의 ATC 값을 덮어쓴다. 우선순위를 화면에 알린다.
9원점 확인그리기 시작은 원점 설정 여부를 확인 대화상자로만 묻는다. 원점 미설정 시 시작을 막는다.
10실측 보정펜 팔 길이, 회전 배율(cal_rot_scale), 서보 값은 실측 후 보정 창에서 입력해야 한다.
